# Experiment 3: Tool-Using Agent — The Function-Calling Pattern

## Aim
To implement the runtime half of LLM function calling — parsing a structured tool call, dispatching it to a registered Python function, and returning the result as an observation the agent can reason over.

## Algorithm
1. Implement each tool as an ordinary Python function, register the functions in a name → function dictionary (the tool registry), and write a JSON schema for each one giving its name, description and argument types — the artifact a real model is shown.
2. Implement `dispatch()`: parse the JSON tool call, look the name up in the registry, invoke the function with the unpacked arguments and wrap the return value in a structured observation; then feed a scripted sequence of tool calls through it, printing each call with the observation it produced.

## Pipeline (LLM Function Calling Workflow)

```text
       [ User ] 
          |
    (1) User Query
          |
          v
[ Language Model (Brain) ] <--- Knows about available Tools (Schemas)
          |
    (2) Tool Call (JSON)
          |
          v
[ Python Script (Hands) ]
          |
    (3) Invokes Function
          |
          v
[ Tool (e.g., Calculator) ]
          |
    (4) Returns Result
          |
          v
[ Python Script (Hands) ] ---> Wraps result into "Observation"
          |
    (5) Observation (JSON)
          |
          v
[ Language Model (Brain) ]
          |
    (6) Final Answer
          |
          v
       [ User ]
```

1. **The Menu (Schema Definition):** The AI model is provided with a list of allowed tools along with their schemas (descriptions and required arguments).
2. **The Decision (Tool Call Generation):** When a user asks a query, the model realizes it needs external help and generates a structured JSON request (a tool call) instead of a regular text response.
3. **Execution (The Runtime):** Our Python script (`dispatch` function) intercepts this JSON, parses it, finds the correct tool in its registry, and safely executes the Python function with the provided arguments.
4. **Observation (Feedback Loop):** The script takes the output of the function, wraps it in an observation, and returns it to the AI. The AI then uses this information to formulate its final answer for the user.

## Observations
- **Execution Side**: The runtime environment (our Python script) executes the tool. The LLM simply decides which tool to call and provides the arguments.
- **Why separation matters**: This separation ensures security and control. The LLM cannot execute arbitrary code or access the system directly. Side effects and real-world interactions only occur through developer-controlled functions (like the restricted calculator).
- **Unregistered Tool**: If the model names a tool not in the registry, the `dispatch` function catches the error (e.g., `Unknown tool`) and returns it as a structured error observation instead of crashing the program, allowing the model to correct its mistake.
- **Schema Requirements**: The schema must contain the tool's exact `name`, a clear `description` of what it does so the model understands its utility, and detailed `parameters` (with types and descriptions) so the model knows what arguments to provide when formulating the JSON call.

## Exercises

### Exercise 1: Error Handling
Error handling was added to `dispatch()` to handle malformed JSON, unknown tool names, incorrect argument types/names, and exceptions inside tools.

**Outputs:**
```
Malformed JSON:
Tool Call: {"name": "calculator", "arguments": {"expression": "pow(2, 3)"}
Observation: {"error": "Malformed JSON: Expecting ',' delimiter: line 1 column 64 (char 63)"}

Unknown Tool:
Tool Call: {"name": "unknown_tool", "arguments": {}}
Observation: {"error": "Unknown tool: unknown_tool"}

Wrong Argument Name:
Tool Call: {"name": "calculator", "arguments": {"expr": "pow(2, 3)"}}
Observation: {"error": "Wrong argument name/type for calculator: calculator() got an unexpected keyword argument 'expr'"}

Exception inside tool:
Tool Call: {"name": "calculator", "arguments": {"expression": "1 / 0"}}
Observation: {"error": "Exception inside tool calculator: division by zero"}
```
